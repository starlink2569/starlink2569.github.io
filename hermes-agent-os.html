1) สรุปรวม: คลิปนี้กำลังบอกอะไร?

คลิปนี้เสนอแนวคิดว่า AI ที่เราใช้กันทุกวันนี้เก่งอยู่แล้ว แต่การใช้งานมักกระจัดกระจาย: Claude อยู่แท็บหนึ่ง, ChatGPT อยู่อีกแท็บ, notes อยู่คนละที่, และทุกครั้งที่เปิดแชทใหม่ต้องเล่า context ซ้ำทั้งหมด

Hermes Agent OS ถูกเล่าในคลิปว่าเป็น Agent Operating System หรือ “โต๊ะทำงานกลาง” ที่ให้ Agent หลายตัวใช้ dashboard เดียว memory เดียว และทำงานตามเวลาได้เอง

ตัวอย่างบ้าน ๆ: เดิมเหมือนมีพนักงานเก่ง 5 คน แต่แต่ละคนอยู่คนละตึกและไม่มีสมุดงานร่วมกัน พอจะสั่งงานต้องเล่าเรื่องบริษัทใหม่ทุกครั้ง ส่วน Agent OS คือย้ายทุกคนมาอยู่โต๊ะเดียวกันและอ่านสมุดงานเล่มเดียวกันค่ะ

2) The Problem: AI Tools Without Shared Memory

ปัญหาหลักไม่ใช่ AI ไม่ฉลาด แต่คือ AI แต่ละตัวไม่มีความจำร่วมกัน พอเริ่มแชทใหม่ ทุกอย่างกลายเป็น blank slate

Old Setup

หลายแท็บ หลาย Login

คำตอบและไฟล์กระจายไปหลายที่ ทำให้ตามงานยาก

No Memory

ต้องเล่าซ้ำ

ธุรกิจ ลูกค้า สไตล์ และ decision เดิมต้อง copy/paste ใหม่

No Autonomy

ต้องนั่งกดเอง

ถ้าเราไม่อยู่หน้าจอ งานก็ไม่เดินต่อ

3) One-Screen AI Team Framework

One Screen, One Brain คือ framework ที่ให้ Agent ทุกตัวอยู่หลัง dashboard เดียวและใช้ shared memory เดียวกัน ผู้ใช้ไม่ต้อง “ไปหา AI ในหลายเว็บ” แต่ให้ AI มี desk ของตัวเอง

ตัวอย่าง: ถ้าวันนี้ให้ Hermes สรุปคู่แข่ง พรุ่งนี้ให้ Claude Code ทำหน้าเว็บ ทั้งสองงานควรอ่าน context ธุรกิจชุดเดียวกัน ไม่ใช่เริ่มจากศูนย์ทุกครั้งค่ะ

4) Hermes Dashboard: Mission Control

คลิปยก dashboard เป็นศูนย์ควบคุมที่เห็นว่า Agent ตัวไหน online, กำลังทำอะไร, และมี activity อะไรเกิดขึ้นบ้าง

Hermes Chat

ช่องคุยหลักกับผู้ช่วย ข้อความและ context ถูกบันทึกไว้

Hermes Apollo

voice side — คุยกับ assistant ด้วยเสียง เหมือนโทรคุยกับเลขา

Hermes Oracle

competitor watcher — ตั้งเวลาให้ตรวจคู่แข่งและรายงานกลับ

Hermes Astros

keyword / content idea watcher สำหรับหาไอเดียทำคอนเทนต์

Live Activity

ดูงานที่เกิดขึ้นในระบบแบบ mission control

Manage Jobs

ตั้ง scheduled jobs เช่น weekly report หรือ market monitoring

5) Persistent Memory with Obsidian

Obsidian ในคลิปถูกอธิบายแบบง่าย ๆ ว่าเป็น folder notes บนคอมพิวเตอร์ ทุก session, decision, task และ business context ถูกเก็บให้ค้นหาได้

ข้อสำคัญคือ Agent หลายตัวอ่านจาก vault เดียวกัน ทำให้การเปลี่ยนโมเดลหรือใช้เครื่องมือใหม่ไม่ทำให้ memory หาย

ตัวอย่าง: ถ้าหัวหน้าเคยบอกว่า “ชอบคำอธิบายแบบบ้าน ๆ” ระบบที่มี memory ดีควรจำ style นี้ได้ในงานถัดไป โดยไม่ต้องบอกซ้ำค่ะ

6) From Prompts to Tickets: Kanban Agent Work

แทนที่จะพิมพ์ prompt ทีละบรรทัด คลิปเสนอแนวคิดให้เขียนงานเป็น ticket บน Kanban board เช่น To Do → In Progress → Done แล้ว dispatcher ส่งงานให้ worker agent ทำเบื้องหลัง

ตัวอย่าง: ก่อนกินข้าวกลางวัน เขียน ticket ว่า “เขียน email promotion 5 ฉบับ” กลับมาตอนบ่าย งานย้ายไป Done พร้อม draft ให้ตรวจค่ะ

7) Goal Mode: 24/7 Autonomous Work

Goal Mode คือการสั่งเป้าหมายใหญ่ครั้งเดียว แล้วให้ Hermes วางแผน ทำงาน และ loop ต่อเองเป็นเวลาหลายชั่วโมง โดยผู้ใช้ไม่ต้องนั่ง prompt ทีละขั้น

“One goal in, hours of work out.”

ตัวอย่าง: แทนที่จะสั่ง “ค้นข้อมูล → สรุป → ทำตาราง → ทำ HTML” ทีละข้อ เราสั่งว่า “ทำหน้า research brief คู่แข่งให้เสร็จคืนนี้” แล้วให้ Agent แตกงานเองค่ะ

8) Scheduled Jobs / Cron Automation

Cron Jobs คือการตั้งงานให้รันตามเวลา เช่น ทุก 1 ชั่วโมง ทุกวันจันทร์ หรือทุกเช้า 9 โมง คลิปใช้ตัวอย่าง Hermes Oracle และ Astros ที่ตรวจคู่แข่ง/keyword อัตโนมัติ

ตัวอย่างบ้าน ๆ: เหมือนตั้งนาฬิกาปลุกให้ AI ไปเปิดเว็บคู่แข่งทุก 3 ชั่วโมง ดูว่ามีอะไรเปลี่ยน แล้วสรุปส่งให้เรา โดยเราไม่ต้องกดเองค่ะ

9) Model Swapping & Local AI Setup

คลิปบอกว่าโมเดลใหม่ออกตลอด แต่ถ้า workflow และ memory อยู่ใน Agent OS การเปลี่ยนโมเดลก็เหมือนเสียบ chip ใหม่: สมองเปลี่ยนได้ แต่โต๊ะทำงานกับสมุดงานยังอยู่

Premium Models

ใช้กับงานสำคัญที่ต้องการคุณภาพสูง

Free / Local Models

ใช้กับงานทั่วไปเพื่อลด token cost

Same Workflow

เปลี่ยน model แต่ dashboard, memory, scheduled jobs ยังเหมือนเดิม

10) Remote Access with Tailscale

คลิปบอกว่าสามารถให้ dashboard รันบนเครื่องที่บ้าน แล้วใช้ Tailscale เพื่อเข้าจากมือถือหรือคอมเครื่องอื่นได้ เหมือนมี command desk ที่เปิดได้จากทุกที่

ตัวอย่าง: Mac ที่บ้านทำงาน 24/7 ส่วนหัวหน้าเปิด dashboard จากมือถือที่อยู่นอกบ้านเพื่อเช็คงานที่ Agent ทำไว้ค่ะ

11) Old Way vs Agent OS

Old Way

  • 5 tabs / 5 logins
  • Memory แยกกัน
  • ต้องอธิบายธุรกิจซ้ำ
  • ไม่มีงานรันเองถ้าเราไม่กด
  • โมเดลใหม่ = เริ่ม context ใหม่

Agent OS Way

  • One screen
  • Shared memory
  • Agent จำบริบทเดิมได้
  • Cron jobs ทำงานตามเวลา
  • Model ใหม่ = เสียบเข้าระบบเดิม

12) Key Takeaways

  • จุดแข็งไม่ได้อยู่ที่โมเดลอย่างเดียว แต่อยู่ที่ระบบรอบตัว AI
  • Shared memory ช่วยลดการอธิบายซ้ำและทำให้ Agent ต่อเนื่องขึ้น
  • Dashboard เปลี่ยน AI จาก chatbot เป็นทีมงานที่บริหารได้
  • Goal Mode เหมาะกับงานใหญ่ที่ต้องทำหลายขั้นตอน
  • Cron jobs ทำให้ AI ทำงานแม้เราไม่ได้อยู่หน้าจอ
  • Model swapping ทำให้ระบบไม่ผูกกับโมเดลใดโมเดลหนึ่ง
